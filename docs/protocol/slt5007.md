# SLT5007 — Murata binary protocol (RS-485, multi-sensor)

SLT5007 uses the same binary frame as SLT5006, but the function-code byte encodes
the sensor number so multiple sensors can share one RS-485 bus.

## Serial settings (PC side)

| Setting | Value |
|---------|-------|
| Baud rate | 9600 |
| Data bits | 8 |
| Parity | None |
| Stop bits | 1 |
| Interface | RS-485 (half-duplex) |

## Function-code encoding

```
FunctionCode = (SensorNumber << 2) | ReadWrite
  ReadWrite = 0  -> Read request
  ReadWrite = 1  -> Read response
  ReadWrite = 2  -> Write request/response
```

Example: sensor number 3 uses `0x0C` for a read request and `0x0D` for its
response. A write request and response use `0x0E`.

The rest of the frame (Address, Size, Data, CRC) is identical to
[SLT5006](slt5006.md).

## Addressing

The sensor number can be changed by writing the sensor-number register at
`0x23`. Valid sensor numbers are **0-31**. The firmware commits the new number
before it builds the write acknowledgement, so that acknowledgement's function
code contains the **new** sensor number. Subsequent readback also uses the new
number. `read_address()` reads `0x23`; `set_address()` performs that live
readback automatically.

There is no command that asks which sensor numbers are in use, so a bus has to
be scanned by reading from each number in turn (`examples/scan_addresses.py`).
Before changing a number, confirm that the requested number is unused while all
bus devices are powered, or connect only the target sensor. The
`examples/set_address.py` script performs that probe and refuses to write if it
receives either a valid or an invalid response at the requested number.

Writing to the clear-number register resets the sensor number to 0. That write
is accepted no matter which sensor number it is addressed to, and it is not
acknowledged, so only connect one sensor when using it.

After changing an address, turn the sensor power source off without connecting
or disconnecting energized wiring, wait a few seconds, restore power, and run
`examples/verify_address.py` with the serial number printed by
`examples/set_address.py`. This checks both non-volatile retention and that the
same physical sensor answered.

> Only read/write the customer-public registers documented in the datasheet.
