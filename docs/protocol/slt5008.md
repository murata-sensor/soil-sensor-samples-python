# SLT5008 — SDI-12 (via TBS03 converter)

SLT5008 speaks **SDI-12**. In these samples the PC connects to the sensor through
a **Tekbox TBS03 SDI-12/USB converter**. A TBS01A evaluation board is also
usable, but the bare TBS01A is a 3.3 V UART module rather than a USB converter.
When using the evaluation board, its USB-derived 5 V sensor output is outside
the SLT5008 supply rating: provide the sensor with an external 9.6-16.0 V
supply (normally 12 V) and connect the grounds together.

## Serial settings (PC side)

> IMPORTANT: Configure pyserial for the **host side of the converter**, not for
> the native SDI-12 line.

| Link | Baud | Data | Parity | Stop | Flow control |
|------|------|------|--------|------|--------------|
| PC <-> TBS03 virtual COM port | 19200 | 8 | None | 1 | None |
| Host <-> TBS01A / TBS01A EVB | Selected by baud pins/jumpers | 8 | None | 1 | None |
| Converter <-> sensor (native SDI-12) | 1200 | 7 | Even | 1 | Handled by converter |

TBS01A supports 4800, 9600, 19200, and 38400 bps; its evaluation board ships
with 9600 bps selected. The `--baud` option only needs to match that selection.
Parity, data bits, and stop bits remain 8N1 on the host side.

The converter generates the SDI-12 break and mark, translates to 1200/7E1, and
controls the bidirectional data line. Do not try to generate those details with
pyserial. TBS03 starts in transfer mode at power-up. If it was manually placed
in another mode, send `run sdi recorder<CR><LF>` and require
`ACK<CR><LF>` before sending sensor commands; this initialization is specific
to TBS03 and must not be sent to a TBS01A.

## Command format

SDI-12 commands are ASCII. `a` is the sensor address (`0`-`9`). The `!` ends the
SDI-12 command; on the PC/UART side, append `<CR><LF>` as the converter's input
delimiter. For example, write `aI!\r\n`. Converter responses also end with
`<CR><LF>`.

| Command | Meaning |
|---------|---------|
| `?!` | Query address — answered by *every* sensor, so use it with only one on the bus |
| `a!` | Acknowledge active — answers `a` only if address `a` exists, so it can probe a bus |
| `aI!` | Identify (SDI-12 version, manufacturer, model, firmware, and serial number) |
| `aAb!` | Change address from `a` to `b` |
| `aM!` | Start measurement (response gives ready time/count; use an early service request if received, otherwise wait `ttt`) |
| `aMC!` | Start measurement and request CRC on the subsequent data responses |
| `aC!` | Start concurrent measurement — same, but the bus is not held and no service request is sent |
| `aCC!` | Start concurrent measurement and request CRC on the subsequent data responses |
| `aD0!` ... `aD2!` | Read measurement data (returned as `a+val+val...`) |

The public API exposes the commands listed above. It does not infer behavior
for command families that are not defined in the product datasheet.

## Identification response (`aI!`)

The public response fields are fixed-width except for the serial number:

| Field | Length | Example | Meaning |
|-------|-------:|---------|---------|
| Address | 1 | `0` | Address of the responding sensor |
| SDI-12 version | 2 | `13` | SDI-12 version 1.3 |
| Manufacturer | 8 | `MurataCo` | Manufacturer identification |
| Model | 6 | `LT5008` | SDI-12 model field; intentionally not `SLT5008` |
| Firmware | 3 | `170` | `170` means firmware version 1.7.0 |
| Serial number | Up to 8 | `22118001` | Sensor serial number |

The response ends with `<CR><LF>`. Validate the response address and fixed
fields before accepting the firmware or serial number.

## Measurement data layout

| Data command | Values, in order |
|--------------|------------------|
| `aD0!` | `DDS`, `ADC_EC`, `ADC_PERMITTIVITY`, `ADC_BATTERY`, `TEMP`, `EC_BULK` |
| `aD1!` | `VWC`, `EC_PORE` |
| `aD2!` | `VWC_ROCK`, `VWC_COCO`, `EC_PORE_COCO` |

`aD2!` is available in firmware 1.7.0 and later. The high-level measurement
APIs in this repository implement and strictly validate that full layout, so
use them with SLT5008 firmware 1.7.0 or later. `read_info()` remains available
to identify firmware before starting a measurement.

The `aM!`/`aMC!` response is `atttn`. Its one-character `n` field must be `8`
because of the SDI-12 response format, but SLT5008 also makes the three
`aD2!` values available. These samples therefore intentionally read `aD0!`,
`aD1!`, **and `aD2!` after an M measurement**. The `aC!`/`aCC!` response has a
two-character value count and reports `11`. The library rejects other counts
instead of silently applying the wrong field layout.

## CRC-protected measurement

`aMC!` and `aCC!` request a CRC on each subsequent `aD0!` ... `aD2!` response.
The start response itself is the normal `atttn`/`atttnn` response. For every
data response:

- CRC polynomial: `0xA001` (reflected, LSB first)
- Initial value: **`0x0000`**
- Input bytes: ASCII from the response address through the last data character
- Excluded: the three CRC characters and `<CR><LF>`
- Encoding before `<CR><LF>`:
  - `0x40 | (crc >> 12)`
  - `0x40 | ((crc >> 6) & 0x3F)`
  - `0x40 | (crc & 0x3F)`

Do not use the `0xFFFF` initial value used by SLT5005/5006/5007/5009. Reject
the complete measurement if any D response has a missing or mismatched CRC.

## Address change

For `aAb!`, the valid response is the **new address `b`** followed by
`<CR><LF>`. Update the local address only after receiving that exact response.
Then verify the new address with `b!` or `bI!`. The sensor retains the changed
address when power is removed. Allow the specified 1-second address-change
settling period before verification. Before writing, confirm that the new
address is unused while all bus devices are powered, or connect only the target
sensor; `examples/set_address.py` performs this check. For the retention test,
turn the sensor power source off without connecting or disconnecting energized
wiring, wait a few seconds, restore power, and verify the address again.

## Typical flow

1. Send `aM!`; validate `attt8`, then wait for the service request or the
   declared `ttt` time.
2. Read `aD0!`, `aD1!`, and `aD2!`, even though `n` is `8`.
3. Parse the `+`/`-` separated fields and apply per-value scaling.

For protected transfer, replace `aM!` with `aMC!` and verify the three-character
CRC on every D response before using its values.

## Multiple sensors on one bus

With several sensors on one SDI-12 bus, using `aM!` for each in turn means
waiting for each sensor's full measurement before starting the next (the bus is
held during `aM!`). `aC!` instead frees the bus immediately, so every sensor's
conversion can run at the same time: send `aC!` to each sensor first, wait out
the longest `ttt` reported in the responses, then read `aD0!`/`aD1!`/`aD2!` from
each. The library's `read_concurrent()` (used automatically by `read_measurement.py`,
`continuous_log.py` and `gui_monitor.py` for 2+ SLT5008 sensors) implements this
sequence.

Unlike `aM!`, a concurrent measurement sends **no service request** when it
finishes — the SDI-12 specification requires the recorder to wait `ttt` seconds
instead. Addressing a sensor before its conversion finishes aborts that
measurement, so do not poll `aD0!` early.

> See the SLT5008 datasheet for the exact data field order and scalings.
